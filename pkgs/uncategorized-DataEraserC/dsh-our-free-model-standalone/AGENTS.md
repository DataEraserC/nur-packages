# dsh-our-free-model-standalone 打包经验

- **与 `../dsh-our-free-model` 同源同 tag**（`Ebony-Vinyl/dsh-our-free-model` v2.2.0，同一 `hash` 字面量，两个包共享同一个 store 源码路径）：插件包只装 `package.json` `files` 白名单的 40 个文件，本包装**整棵树**——上游 standalone README 明言「原渠道的 WASM 和共享核心仍来自完整仓库，单独复制 packages/standalone 不能运行」，运行期相对导入逃出该目录：`service.mjs` → `../../src/core/runtime.js`、`../../src/forward.js`、`../../src/trust.js` 等，`channels/business.mjs:37023` 硬编码 `new URL("../../../vendor/channel-pack/qoder-auth-wasm.wasm", import.meta.url)`（`fileURLToPath`，路径写死、不能挪布局），`service.mjs:12` 读 `./package.json` 取 version。所以 `installPhase` 直接 `cp -r . $packageDir/`，包目录 = 上游仓库根布局（`$out/lib/our-free-model-standalone/`），CLI 入口指向 `packages/standalone/cli.mjs`
- **checkPhase 前 `rm -rf .git` 的顺序坑**：本包 checkPhase 沿用插件包的 `git init -q`（见 `../dsh-our-free-model/AGENTS.md`：release-preparation/vault 套件要 git），init 出来的 `.git` 若不删会被 `cp -r .` 拷进产物；`installPhase` 开头先 `rm -rf .git` 再拷。插件包无此问题因为它只拷白名单条目
- **零 npm 运行时依赖，但 checkPhase 需要 nodejs 进 nativeBuildInputs**：`packages/standalone/package.json` 的 devDependencies（vite/react/esbuild）只用于 `web/` 前端构建，而 `web/` 是**提交好的构建产物**（`app.js`/`index.html`/hash 命名 chunk + `assets.json` 清单，`management.mjs:93` 读它路由静态资源），运行期 import 全是 `node:` 内置模块，故不装 node_modules、不跑 npm。但 `__structuredAttrs` + `strictDeps` 下 checkPhase 的 `node scripts/test-all.mjs` 不在 PATH——`nodejs` 必须列进 `nativeBuildInputs`（插件包走 buildDshBundle 自带 node，没这个坑）
- **postPatch 两条测试修复与插件包完全相同**（`forward-test.mjs` 离线 DNS 放宽、`standalone-login-terminal-test.mjs` 的 `/usr/bin/printf` 换内建 `printf`），原因详见 `../dsh-our-free-model/AGENTS.md`；`scripts/` 不在 `catalog/integrity.json` 的 40 文件清单里，改测试不破坏 sha256 验收
- **产物验收复用上游签名清单**：整树安装后 `catalog/integrity.json` 的 40 个文件全部存在于 `$packageDir/`，`postInstall` 照插件包展开成 `sha256  path` 喂 `sha256sum --check --strict`，等于验证「整树 = 上游发布物逐字节」；另加三个存在性断言（CLI 入口、`web/index.html`、wasm）
- **`installCheckPhase` 跑包装器本身**：`grep -q "Our Free Model" <($out/bin/our-free-model-standalone --help)`——同时验证 makeWrapper 的 node 路径可执行、`--help` 分支在安装布局下工作（`--help` 在读 `package.json`/import service 之前的 argv 循环里就返回，安全）。CLI 无 `--version`，versionCheckHook 用不了
- **wrapper 三件套**：`--add-flags $packageDir/packages/standalone/cli.mjs`（入口）+ `--set NODE_ENV production`（仓库 Node 包通用规则）+ `--prefix PATH : makeBinPath [ mihomo xdg-utils ]`——`src/egress.js` 的 `findMihomoBinary` 扫 PATH 找 mihomo/clash-meta，`channels/business.mjs:1414` 起子进程跑 `xdg-open`（`openExternal`）。与插件包 runtimeDeps 同款，但 stdenv 包没有 buildDshBundle 的 runtimeDeps 注入，必须手写 PATH
- **登录终端取令牌在 Linux 上本来就不支持**：`login-terminal.mjs` 只实现 darwin（osascript+pbcopy）与 win32（PowerShell Set-Clipboard），`platform !== 'win32'` 非 macOS 直接 throw 400「自动打开终端仅支持 Windows 和 macOS，请按页面说明手动获取令牌」——所以 Linux 包**不需要** clipboard 工具（xclip/wl-clipboard），网页会走手动入口
- **引擎要求 node ^22.19 || >=24**（根与 standalone 两个 package.json 同款 engines），nixpkgs `nodejs` 24.21.0 满足；`--data-dir`/`OFM_HOME` 默认 `~/.our-free-model`，数据目录含 `settings.json`（`forwardKey`）、`service.lock`、账号池，运行期可写，不能烤进 store
- **`updateScript` 用裸 `nix-update-script { }`**：本包不依赖 deepseek-harness flake 输入（纯 stdenv），无需插件包那套 `--flake` + 裸 attrPath 特例；但注意两个包版本独立推进，上游发新版时两个包要一起更（同一 src 哈希）
