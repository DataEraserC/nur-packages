# dsh-notifier（DSH 通知与远程控制插件）

- **src 必须用 `fetchFromGitHub` 的 tag，不能用 npm tarball**：npm 发布包的 `files` 白名单带 `test/` 却不带 `examples/`，而 `test/consumer-demo.test.mjs` 在模块加载期就读 `examples/consumer-demo/package.json`——用 `registry.npmjs.org` 的 tgz 当 src 时测试必挂 1 个（实测 1826/1827，本地裸跑报 `ENOENT .../examples/consumer-demo/package.json`）；GitHub tag 的源码树完整，沙箱内 `npm test` 1831/1831 全过、约 31 秒（admin-server 等测试绑定 127.0.0.1，沙箱 loopback 可用，不需要外网）
- **上游没有 `build` script，但有 `scripts.test`**：`dontNpmBuild = true` 必须设（否则 `npmBuildHook` 报 `no build script was specified`）；`buildDshBundle` 默认不跑测试，要显式 `doCheck = true` + 自定义 `checkPhase` 调 `npm test`（`buildNpmPackage` 不会自动把 `scripts.test` 接进 checkPhase）
- **lockfile 是生成式的，上游不提交 `package-lock.json`**：在包目录提交一份，`postPatch` 里 `cp ${./package-lock.json} package-lock.json` + `chmod u+w`（store 拷入的文件是 444，`npmConfigHook` 的 fixup-lockfile 与 `npm ci` 都要写它）。生成时**不要**加 `--legacy-peer-deps`：peer `@deepseek-ai/cordis` 必须进 lockfile（npm 7+ 自动解析，57 条目、0 devDep、无平台相关 optional 条目），可选 peer `@deepseek-ai/dsh-session` 不会被安装（由 `linkKernelNodeModules` 从 kernel 链入）
- **`update.sh` 是「`nix-update --src-only --flake` → 重新 `npm install` → `prefetch-npm-deps` → `nix build` 验证」闭环**：与同组 dsh-git-worktree 一致，attrPath 用 `${UPDATE_NIX_ATTR_PATH##*.}` 剥掉组前缀（flake 的 packages 只暴露平铺名），nix-update 必须 `--flake`（包依赖 deepseek-harness 输入，legacy 求值必挂）；源码没变直接 `exit 0` 保持幂等，末尾的 `nix build` 把坏 `npmDepsHash` / 坏新版本挡在提交之前
- **产物无 `bin/`（package.json 无 `bin` 字段）→ 不设 `meta.mainProgram`**；版本一致性改用 `doInstallCheck` + 自定义 `installCheckPhase` 校验装出来的 `package.json` version 等于 `finalAttrs.version`（防上游「先打 tag、再 bump 版本」类漂移；NixOS 26.11 的 stdenv 在 fixupPhase 之后跑 installCheckPhase，`node` 在 nativeBuildInputs 里可用）
- **`runtimeDeps = [ libnotify ]`**：desktop 渠道在 Linux 上 `spawn('notify-send', ...)`（`src/adapters/desktop.mjs`），NixOS 默认 PATH 没有该命令；bundle 的 `passthru.runtimeDeps` 由 harness 的 `pkgs/dsh/composition.nix` 汇总、在 dsh 启动器上 `--prefix PATH`（与 turn-rewind 声明 `git` 同一机制）
- **`linkKernelNodeModules` 的实际效果**：kernel `node_modules` 有 214 个顶层条目，本包 56 个依赖里 42 个重叠——`@deepseek-ai/cordis` 4.0.4 被 prune 后链到 kernel（避免双 cordis 实例），`axios` / `@larksuiteoapi/node-sdk` / `qrcode-terminal` 不在 kernel 里保留为本地副本；重叠项中 kernel 版本更“新”的有 `https-proxy-agent` 7（本地 5）、`mime-types` 3（本地 2）、`agent-base` 7（本地 6），只波及 lark SDK 的传递依赖，webhook/Telegram 等主路径不受影响
- **npm 11 会在 `npm pack`/`npm prune` 时警告 `protobufjs` 的 postinstall 未被 `allowScripts` 放行**：该脚本只是 protobufjs 自己的 CLI 后处理，跳过不影响测试与运行，无需处理
