# dsh-our-free-model 打包经验

- 打包必须用 tag 树（`rev = "v${version}"`），不能用 HEAD：HEAD 已把 `vendor/jet-hub/` 改名为 `vendor/channel-pack/`，与 tag 版 `index.js` 的 `import('./vendor/jet-hub/pack.js')` 和 `package.json` 的 `files` 白名单不自洽；tag 树自身自洽
- 本机到 GitHub/codeload/api.github.com 全部不通，src 哈希用 `git archive --format=tar <tag>` 解出的树在本地算：`nix hash path --sri <dir>`。上游 `.gitattributes` 只有 `* text=auto eol=lf`、无 `export-ignore`，codeload tarball 树与 git archive 树逐字节一致，所以该哈希对 `fetchFromGitHub` 有效；落地前用 `nix-store --add-fixed --recursive sha256 source` + `nix-store --print-fixed-path --recursive sha256 <hash> source` 比对、并以 `nix build .#dsh-our-free-model.src` 免网络收尾验证
- **npm ci 不可行，依赖安装整体跳过**：peerDependencies 里的 `dsh-credentials` 未发布到任何 registry（npmjs 与 npmmirror 均 404），lockfile 永远凑不齐；同时 `catalog/integrity.json` 记录了 `package.json` 自身的 size/sha256，任何删 `peerDependencies`/`devDependencies` 的 postPatch 都会被 `manifest`/`catalog`/`release` 三个套件抓住，重建 manifest 又要 `OFM_MANIFEST_KEY` 签名私钥。写法：`npmDeps = null` + `npmConfigHook = pkgs.emptyDirectory`（传 `null` 会回退到默认 `npmConfigHook`，所以给一个没有 setup-hook 的空目录派生占位，等于跳过依赖安装）+ `dontNpmBuild = true`；上游零 dependencies，跳过无损
- 不走默认 `npmInstallHook`：它在白名单拷贝之后无条件 `find/cp -r node_modules`（`dontNpmPrune` 只跳过 prune 那步），无 `node_modules` 必挂，`npm prune` 还要联网。改用自定义 `installPhase` 按 `package.json` 的 `files` 白名单逐条拷贝（`mkdir -p $packageDir/$(dirname $entry)` 保住相对路径）再补拷 `package.json`
- 产物验收用上游自己的签名清单：`postInstall` 把 `catalog/integrity.json`（40 个文件，含 pristine `package.json`）展开成 `sha256  path` 行喂给 `sha256sum --check --strict`，与上游发布物逐字节对齐；需要 `nativeBuildInputs = [ jq ]`
- `checkPhase` 跑 `node scripts/test-all.mjs`（上游 `npm test`），全部套件离线（`release`/`manifest`/`catalog` 只读文件树、不碰网络与 node_modules），实测 30/30；`buildDshBundle` 默认不跑测试，必须显式 `doCheck = true`
- **沙箱里两处缺宿主资源，实测修复**：(1) 沙箱无 git 且 src 是 git archive 树（无 `.git`）——`release-preparation` 套件 `spawnSync git init` 直接 ENOENT、`vault` 套件 `git check-ignore scripts/eac-vault-mint.mjs` 失败落进 catch 断言 false；配方 `nativeBuildInputs = [ git jq ]` + `checkPhase` 里测试前 `git init -q`（`.gitignore` 随 tag 树解出，check-ignore 即过；测试只在各自 scratch 仓库里 commit，不污染源码树）。(2) 沙箱无网络无 DNS（`/etc/hosts` 只读仅 localhost、无 `resolv.conf`、`HOSTALIASES` 被 node 忽略，`resolveLoopbackBind('example.com')` 必 `EAI_AGAIN`、错误串不含 `/loopback/` 断言必挂）——`scripts/` **不在** `catalog/integrity.json` 的 40 文件清单里（postPatch 改测试不破坏 sha256 验收），`postPatch` 用 `substituteInPlace` 把该断言放宽为 `/loopback|could not resolve/`：离线时函数照样拒绝（fail-closed，被测安全性质不变），routable 拒绝逻辑仍由 `8.8.8.8` 字面量断言覆盖
- **上游 2.1.0 的启动器套件把 macOS 的 `/usr/bin/printf` 当可移植工具用，NixOS 上必挂**：`scripts/standalone-login-terminal-test.mjs` 里 `if (process.platform !== 'win32')` —— **Linux 也落进这个分支** —— 把待执行源码里的 node 路径替换成 `/usr/bin/printf '%s\0'`，目的是只回显参数、不真执行那段源码。NixOS 没有 `/usr/bin/printf`（coreutils 只在 store 里），`/bin/sh -c` 找不到命令、`if` 判假走 `else` 分支，于是源码被真的执行并把它自己的「获取令牌失败…」打印到 stdout → `assert.equal(flag, '-e')` 拿到那句提示语（报错现场显示成 `+ '获取令牌失败，请检查本地 settings.json 或使用页面的手动入口。\n'` / `- '-e'`），`standalone-management` 15/16、`test-all.mjs` 44/45 失败，并连锁拖垮 `dsh-0.2.1-alpha.2` 与整机 toplevel。修法：`postPatch` 再补一条 `substituteInPlace scripts/standalone-login-terminal-test.mjs --replace-fail "/usr/bin/printf '%s" "printf '%s"`，用 POSIX sh 内建 `printf`（`/bin/sh -c` 下 `command -v printf` 即内建，bash 亦然）替掉绝对路径，macOS 上同样成立、断言强度不变（patch 后 45/45 全过）。模式里**不要**带 `\0`：`substituteInPlace` 的 shell 转义会把它吃掉，匹配到 `'%s` 已足够唯一
- `runtimeDeps = [ mihomo xdg-utils ]`：订阅 egress 模式下 `findMihomoBinary` 扫 PATH 找 mihomo/clash-meta；`openExternal` 用 `xdg-open` 打开网关 URL（失败也只降级为手动粘贴）
- 产物为扁平布局（`index.js`/`client.js` 在包根），包目录无 `node_modules`，`linkKernelNodeModules` 把整个包目录符号链接进 kernel；无 `bin/`，不设 `meta.mainProgram`
- **加宽 sealed-host 闸门只能改安装副本，不能改源码**：`src/vault.js` 的 `detectSealedHost` 只认 `web`/`web-desktop`/`desktop` 三个 profile 名，自定义 web profile（如 `nix-web-qq`）拿不到 sealed lane。该文件同时被两份签名发布记录覆盖（`catalog/integrity.json` 与 `feed/manifest.json`，各 40 项），而 `build-manifest.mjs --check` 会用 `PINNED_MANIFEST_PUBLIC_KEY` 校验已提交 manifest 的 Ed25519 签名（其 `signature` 覆盖 `files` 列表）——改源码必然使签名失配，而重签需要上游私钥（`OFM_MANIFEST_KEY`）。所以 `postPatch` 改 `src/` 是死路。解法：`extraWebProfiles` 属性（默认 `[ ]`）→ `postInstall` **在** 40 项 sha256 校验**之后**改 `$packageDir/src/vault.js`，pristine 树与所有读它的闸门（`checkPhase`、`postInstall` 摘要）都不受影响；`scripts/` 不在 `files` 白名单所以不参与安装，`src/` 在白名单所以补丁作用在已验证字节之上。实测：默认构建与上游逐字节相同（`diff -r` 无差异），打补丁构建仅 `src/vault.js` 一个文件不同，`nix-web-qq` 与 `nix-web-qq-lan` 双双由 `null` 转 `web`、未列名 `embedded` 仍 `null`，30/30 套件仍通过
- `extraWebProfiles` 是**函数形参**（与 `qq-agent-presets` 的 `extraAllowedTools` 同款：`lib.extendMkDerivation` 会把形参收进产物的 `override` 集合），消费方写 `pkgs.dsh-our-free-model.override { extraWebProfiles = [ ... ]; }`，nix-config 里 `qq-agent-presets` 已是这个用法。**补丁片段用 `lib.concatMapStrings` 在 Nix 层按 profile 展开，不要在 shell 里循环拼列表**：`printf '%s\n' a\nb` 展开进脚本后是**两条命令**（实测第二个 profile 变成 `nix-web-qq-lan: command not found`，静默少打一个），改用 `tr '\0' '\n'` 分隔也会被 Nix 转义吃掉 `\0`（产物里出现 `nix-web-qq0nix-web-qq-lan`）。**插入而非替换**：`substituteInPlace` 会消耗自己的模式，第二个 profile 找不到锚点而被静默丢弃；用 `sed -i "/anchor/i\\..."` 锚在 desktop 行前插入，锚点始终存在
- 构建期三道护栏：名字须匹配 `^[A-Za-z0-9._-]+$`（挡 shell/补丁注入，实测 `a b;rm -rf /` 被拒）、不得与既有 profile 名重复（`grep -qF` 命中即报错退出，避免生成 `profileName === 'web'` 这种死代码）、desktop 锚点必须恰好出现一次（`grep -cxF ... -ne 1`，防上游改版后补丁静默失效）
