# workbuddy 打包经验

- **国际站 Linux 下载已失效，走国内站**：`https://www.workbuddy.ai/v2/update?platform=workbuddy-linux-x64-deb` 返回的 5.5.2 URL 已 404；`https://www.workbuddy.cn/v2/update?platform=workbuddy-linux-{x64,arm64}-deb` 返回可用的 5.6.2 `.deb` 且带 `sha256hash`。两个平台 URL 都带构建哈希后缀（如 `-c7b525f3.deb`），无法从版本号推出，因此用 `release.json` 保存完整 URL；版本变化时用接口返回值重写。
- **`dpkg -x` 解包即可**：deb 只有一个顶层 `/opt/WorkBuddy`（Electron 本体 + 内置 CLI + Python runtime，安装体积约 1.6GB），另有 `usr/share/{applications,icons}`。用 `dpkg` 作 nativeBuildInput，不要走 `ar` + `tar` 手撕。
- **koffi 的跨平台预编译会毒化 autoPatchelf**：`resources/app.asar.unpacked/node_modules/koffi/build/koffi/` 下带了 linux/darwin/win32/freebsd/openbsd/musl 全套绑定，其中 openbsd 变体是 x86_64 ELF 且依赖 `libc++.so.9.0`/`libpthread.so.26.1` 等，autoPatchelf 会按架构放行后报缺依赖。installPhase 里按目标架构只保留 `linux_x64`/`linux_arm64` 子目录（`find ... ! -name "$koffiArch" -exec rm -rf {} +`），musl 变体随之删除；`libc.musl-*.so.*` 的 ignore 仍保留兜底。
- **chrome-sandbox 在 store 里无法 setuid**：wrapper 必须加 `--no-sandbox`，否则 Electron 起不来（SUID helper 权限错误）。Wayland 按仓库 qq 的 ozone 自适应写法透传 `NIXOS_OZONE_WL`/`WAYLAND_DISPLAY`。
- **不需要 versionCheckHook**：这是 GUI 应用，`--version` 会直接进入主进程而不是打印版本；用构建成功 + 实跑主进程验证。实测 `result/bin/workbuddy --version` 能走到 Electron main、加载内置 CLI/Python，只有沙箱里 `/home/...` 不可写导致的正常 ENOENT 噪音。
- **waypipe 下有两个独立故障，别只修一个**：
  1. **启动即卡死、连窗口都没创建**：走 waypipe 默认（DMABUF/GPU）通道时 Chromium 初始化会空转（主进程 CPU 约 37%，无窗口、`--inspect` 不监听）。应用侧开关都无效（实测 `--disable-gpu`、`--use-gl=swiftshader --enable-unsafe-swiftshader`、`--disable-features=WaylandLinuxDrmSyncobj` 均照旧卡住），**只有客户端加 `waypipe -n`（`--no-gpu`）才能过**。这不是打包问题，是 waypipe 与 Chromium 的互操作限制，用法上必须写 `waypipe -n ssh <host> workbuddy`。
  2. **窗口创建了但永不显示**：主窗口 `buildMainWindowOptions` 是 `show: false`，上游唯一 `show()` 在 `ready-to-show` 回调里。Wayland/waypipe 下未 map 的窗口不产首帧，于是 `ready-to-show` 长期不触发（实测 `waypipe -n` 下 98 秒仍 `isVisible()=false`），应用看起来"没启动"。**把 `show()` 塞进 `ready-to-show` 回调内部是无效补丁**（回调本身不跑，属于死代码，旧版打包就是踩了这个坑）。现在改为在窗口创建后挂 1 秒兜底定时器：`ready-to-show` 正常触发时窗口已可见、定时器空转；waypipe 下由定时器负责 `show()`。
  诊断手法（可复现）：`workbuddy --inspect=9339` + CDP 向主进程求值 `require('electron').BrowserWindow.getAllWindows().map(w=>({visible:w.isVisible(),bounds:w.getBounds()}))`；再用 `webContents.capturePage().toPNG()` 截图确认 renderer 真的画出了界面（实测正常）。手动 `.show()` 能立刻让窗口出现，也顺带证明"只差一次 show()"。
- **改 asar 内容要自己重打包，不能拆目录**：目录模式（解包成 `resources/app/`）会让 `app.isPackaged` 变 `false`，asar 里有 72 处引用它，会触发 dev-mode 分支；而且原 asar 的 fuse `OnlyLoadAppFromAsar` 与 `EnableEmbeddedAsarIntegrityValidation` 都是 disabled（实测解出 fuse wire `10110001`、纯目录 app 能加载），所以重打包既不触发校验也不改变运行时行为。重打包器 (`repack-asar.py`) 只改目标文件的 size/offset/integrity 并保持其余文件物理顺序；**未改动时往返重建必须逐字节一致**（`identical=True` 是回归基线）。Linux 没有 asar 完整性校验：`validateMacAsarIntegrity` 唯一调用点在 `[darwin]` 更新流程里。
- **应用自带 safe-bin 删除 shim 写死 FHS 路径，在 NixOS 上是 `bad interpreter`**：`resources/app.asar.unpacked/cli/vendor/shim/safe-bin/{rm,rmdir,unlink}` 的 shebang 是 `#!/bin/bash`（NixOS 无 `/bin/bash`），且 `safe-delete-common.sh` 里真实删除程序写死 `/bin/rm`、`/usr/bin/rm`、`/usr/bin/unlink`。只修 shebang 会把报错变成「找不到 /usr/bin/rm」，两处必须一起修：`patchShebangs` 修 shebang + wrapper 里 `--set SAFE_DELETE_REAL_{RM,RMDIR,UNLINK}` 指向 coreutils（这三个变量名是脚本自己读的）。注意 `brokered-bin/` 下那套同名 shim 用的是 `#!/usr/bin/env sh`，不受影响，别顺手一起改。
