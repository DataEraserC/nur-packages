# bstar（QQ NT 的 V8 注入库，闭源预编译）

- **二进制不进 git，走本仓库自己的 release 资产**：`bstar-0.5.10.so`（5.0 MiB）与 `liblightweight-v8-inject.so`（5.6 MiB）曾长期以二进制形式提交在包目录里（`4dec34da` 引入），每次 clone 与 CI checkout 都要拖这份闭源产物。现在两者都上传到 [release `bstar-0.5.10`](https://github.com/DataEraserC/nur-packages/releases/tag/bstar-0.5.10)，`bstar.nix` 用 `fetchurl` 从该 release 拉取并校验 `hash`；包目录只剩 `.nix`。上游（ChronoNeko）没有公开源码仓库或 release 页，这份 release 是我们唯一的稳定分发点，**不要**把 `.so` 再提交回仓库。
- **`liblightweight-v8-inject.so` 只作参考，不进产物**：它是同一项目另一种构建，实测在当前 QQ NT 上非 CC 与 CC 两种模式都出不了窗口（见 `bqqnt/AGENTS.md`），因此不作为包内容安装，只挂在 `passthru.lightweightV8Inject` 上保持可达（`nix build .#bstar.lightweightV8Inject`）。把它换进 `src` 会做出一个能构建、但运行必挂的包。
- **release 资产改名必须同步改 `releaseBase` 与 `hash`**：URL 里的 tag（`bstar-0.5.10`）和文件名都写在 `bstar.nix` 的 `releaseBase` 里，`version` 只驱动文件名插值 `${finalAttrs.version}.so`。换版本时同时更新 tag、`version`、两个 `hash`（用 `nix store prefetch-file --json <url>` 取值），并把旧 release 的 `SHA256SUMS` 与新资产一并核对。
- **两个 `.so` 的来源已核实到可机器验证的程度**：二者都是 ChronoNeko 随 ChronoCat 发布的闭源构建（`.so` 内嵌 ChronoCat/Satori 的 JS，含 `chronocat.vercel.app`、`github.com/chrononeko/chronocat/releases/latest` 等字符串），2024-11-09 以文件形式发在 ChronoNeko 的 QQNT 频道（`@bqqnt`）；`bstar-0.5.10.so` 与 `Anillc/chronocat.nix` 里按哈希钉住的同名文件逐字节一致（`sha256 = "032q8mm7n4apyfmd7ba9dpfnbky9jk6vrnn08nnjnj8zyi3a75r3"`，即 SRI `sha256-I5ejRvQfSSutRcDavM2Uyc9l3W1JrdOq81cRe2pFWAw=`）。上游只有二进制、没有可复现构建，所以本包只能 `fetchurl` 预编译产物，`meta.sourceProvenance` 标 `binaryNativeCode`。
