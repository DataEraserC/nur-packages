# bqqnt（在 nixpkgs `qq` 之上只加一层）

- **依赖 `pkgs.qq`（nixpkgs），不要依赖 fork 自带的 `pkgs/uncategorized/qq`**：`createCallPackage` 用 `callPackageWith (pkgs // _packages // …)`，自有同名包会遮蔽 nixpkgs 版本，`qq` 形参拿到的是自有旧版（3.2.18，wrapper 没有 Wayland flag）；自写启动脚本 `exec ${qq}/bin/qq` 会丢掉 nixpkgs `qq` wrapper 在 `NIXOS_OZONE_WL`+`WAYLAND_DISPLAY` 下加的 `--ozone-platform=wayland --enable-features=WaylandWindowDecorations --enable-wayland-ime=true --wayland-text-input-version=3`，Wayland 下 Electron 既不建 text-input 也不走 XIM，fcitx5 完全打不出中文。把 `pkgs` 写进参数表再用 `pkgs.qq`（nixpkgs 的 `pkgs.pkgs` 存在，注入的合并集里取得到），版本与依赖就跟着 flake.lock 走，不必在本仓库维护上游派生；本包无 `passthru.updateScript`，更新跟随 flake.lock（`helpers/update.nix` 的 excludes 注释即指这类纯 wrapper）。
- **只加一层用 `symlinkJoin { paths = [ pkgs.qq ]; … }`**：`lndir` 造真目录 + 文件 symlink，`bin/qq`、`share/applications/qq.desktop` 与图标都是上游自己的文件，原版入口天然带 flag；postBuild 只补 `bin/bqqnt`（`--set LD_PRELOAD=bstar`）与 `qq2.desktop`。要点：(1) `makeWrapper` 不能写到已存在且指向 store 的 symlink 上（对只读 store `echo > $wrapper` 会 EACCES），先 `rm -f`；(2) `sed -i` 会把 store symlink 换成真文件，不会改到 store 原件；(3) `symlinkJoin` 不继承 `meta`，`description`/`platforms` 要自己给（`meta = qq.meta // { … }`；此时 `meta.position` 落在自己的文件上，`tools/build_own_cachix.py` 会把它算作自有包，而继承上游 meta 会被它的路径过滤掉）；(4) 上游 wrapper 用 `--prefix LD_PRELOAD` 追加自己的库（nixpkgs 的 qq 插 libssh2），外层 `--set LD_PRELOAD=bstar` 不会被清掉，两个库都加载。
- **无 GUI 验证法**：把 `qq` 换成打印 `"$@"`/`$LD_PRELOAD` 的 stub（`callPackage … { pkgs = pkgs // { qq = stub; }; }`）即可断言注入与参数都在；若要在自己的 wrapper 里补 flag，条件写法是 `--add-flags "\''${NIXOS_OZONE_WL:+\''${WAYLAND_DISPLAY:+…}}"`（只有 `\''${` 同时躲开 Nix 插值并把 `$` 留给运行时 shell）。

## 两条注入路径：`bin/bqqnt` 与 `bin/bqqnt-cc`

- `bin/bqqnt`（不设 `BQQNT_CC`）= bstar 的通用 V8 注入：写一个 `/tmp/lwv8.js` bootstrap 去动 QQ 的 `launcher.js`（`.so` 里可见 `launcher_js` / `launcher_js_str` / `/proc/self/cmdline` / `--type=` / `lwv8.js`），最后 `require('./launcher.node')`。store 里三个 QQ 构建（自有 3.2.18、nixpkgs 两个 3.2.32）的 `app_launcher/` 下都只有 `launcher.js`、没有 `launcher.node`，所以这条路径在 3.2.32 上稳定报 `Cannot find module './launcher.node'` 并且**完全不出窗口**（桌面实测）。要用它得先有提供 `launcher.node` 的客户端模组。同一个 bstar、同一条路径在 qq 3.2.18（上游自有 `pkgs/uncategorized/qq`，用 `bqqnt.override { pkgs = pkgs // { qq = …; }; }` 构建）下**能正常出窗口**，只是那份 qq 的 wrapper 没有 Wayland flag 所以没有输入法；因此这是 bstar 的启动注入与新 QQ 不兼容，打包层修不了（`.so` 是闭源预编译，上游 ChronoCat 2024-10 发完 0.2.19 就停更）。
- `bin/bqqnt-cc`（`--set-default BQQNT_CC 1`，环境变量可覆盖）= 启用 `.so` 内嵌的 ChronoCat（模块化的 Satori 框架）：`chronocat` / `satori` 的 JS 就在 `.so` 里（`https://github.com/chrononeko/chronocat/releases/latest`、`chronocat.vercel.app/connect`、`e.chronocat.uix.getUid2` 等字符串可证）。上游 ChronoCat 自己的 Nix 打包注入方式也正是 `LD_PRELOAD=.../bstar.so BQQNT_CC=1 exec qq`（`Anillc/chronocat.nix` 的 `modules/bstar.nix`，旧 `ChronoCat_bqqnt` 即抄自它）。桌面实测 3.2.32 下正常。
- 仓库里另有一份 `liblightweight-v8-inject.so`（同属 ChronoCat 0.2.19 的另一份构建，`bstar.nix` 里被注释掉的那行就是指它）：实测把它当作包里的 `.so` 时**非 CC 和 CC 两种模式都出不了窗口**，比 `bstar-0.5.10.so` 更差；文件保留但不要换用。
- 两个入口都保留：`qq2.desktop`（Name=bqqnt）指 `bin/bqqnt`，`qq3.desktop`（Name=bqqnt (ChronoCat)）指 `bin/bqqnt-cc`；两个 desktop 由同一份 `qq.desktop` 拷出后 sed 改 Exec/Name，原版 `qq.desktop` 仍是尚未注入的上游入口。`qq2.desktop` 在当前 qq 上点不出窗口，这是已知情况（用户选择保持现状、不再调整桌面项）。
- 另一类“启动出现错误”弹窗与 bstar 无关：nixpkgs 的 `qq-version-config.sh` 按当前 qq 版本写 `~/.config/QQ/versions/config.json` 并 `chmod u-w`（表现为 `-r--r--r--`），此后启动另一个版本的 QQ 时，QQ 自己的 `app_launcher/launcher.js` 先 `unlink` 再重建该文件，写不进去就抛 EROFS/EACCES、弹窗且不出窗口；不要在同一个 `~/.config/QQ` 下混跑两个 QQ 版本。该脚本另有上游小 bug：写 JSON 的 heredoc 没加引号，注释里的反引号 ``disableAutoUpdate`` 被当成命令替换执行，会打印 `disableAutoUpdate: command not found`（纯噪音，值得给 nixpkgs 报一下）。
- 调试提示：harness 沙箱里 `~/.config/QQ` 是只读挂载，跑 store 二进制时 launcher 的行为不可信，以桌面实测为准。
